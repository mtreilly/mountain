# Discoverability plan

Make Mountain to Climb findable for "economic convergence" topics and usable by LLM agents
as a calculation engine, without rewriting the SPA.

## Constraints from the current design

- Vite SPA served from Cloudflare (Pages → Worker migration in flight: `worker/index.ts`
  routes by hand, assets via `env.ASSETS`). New routes are added there.
- All surfaces share `src/lib/convergenceModel.ts`. `scripts/test.ts` fails if
  `Math.log(...) / Math.log(...)` or `Math.max(baseYear…` appear elsewhere, so every new
  endpoint and page goes through `convergenceOutcome` / `loadPairOutcome`-style helpers.
- Data is a build-time snapshot read through `ASSETS` (no D1 at request time).
- `/share` and `/api/og.png` already give server-rendered metadata and a chart image.
- Server-rendered pages are English only (like `share.ts`); the SPA i18n files are untouched.

## Decisions

- **Scenario, not forecast.** Every response and page says the result follows from stated
  growth assumptions.
- **Raw data by default.** API and compare pages use unadjusted published values (they match
  the cited World Bank figures) and carry `caveats` for countries with a known measurement
  quirk (Ireland, Luxembourg, Gulf states, …). `adjusted=true` opts into the app's factors;
  links into the app carry `adjC`/`adjT` explicitly so page and app agree.
- **Page defaults are trailing 10-year growth rates** for each side (clamped to the app's
  slider range), rounded to 0.1 pp. That makes a page a factual statement, not an arbitrary 4% vs 1%.
- **Curated pair pages.** Any valid pair renders, but only curated pairs are in the sitemap
  and indexable; others are `noindex` to avoid thin near-duplicate pages.
- **Keep `/share?…` as the shareable-state URL.** No second `/c/…` scheme.
- **No `Dataset` structured data** (we redistribute third-party data). `WebApplication` only.
- Deferred: WebMCP, essay pages (`/catch-up-growth` …) beyond the homepage explainer.

## Status

Phases 1–6 are implemented and covered by `app/scripts/discoverability.test.ts`
(run as part of `pnpm test`). Not yet verified against a deployed Worker.

## Phases

### 1. Homepage head and crawlable text
- `index.html`: title "Economic Convergence Calculator — Mountain to Climb", description,
  canonical, OG/Twitter on `mountaintoclimb.com`, JSON-LD `WebApplication`.
- ~400 words of real HTML inside `#root` (replaced when React mounts): what convergence is,
  catch-up growth, the formula, what the calculator does, links to API/llms.txt.
- **Outcome:** `curl -s /` contains the explainer and JSON-LD.

### 2. `llms.txt`, `robots.txt`, `sitemap.xml`
- Static `public/llms.txt` (tool-oriented), `public/robots.txt` (allow `OAI-SearchBot`,
  `GPTBot` unchanged/allowed, sitemap link). `/sitemap.xml` generated by the worker from the
  curated list.
- **Outcome:** all three return 200 with correct content types.

### 3. API: shared scenario core + extended endpoints
- `worker/_lib/scenario.ts`: pair data, trailing CAGR, history + projection series, caveats.
- `/api/convergence` (calculate_convergence): additive `target_growth_rate`, `base_year`,
  `adjusted`; adds `scenario`, `series`, `caveats`, `source`, `methodology`, `links`.
  Legacy fields kept.
- `/api/compare` (compare_countries): latest values, ratio, trailing growth.
- `/api/required-growth` (growth_required_by_deadline): chaser growth needed to catch up by year Y.
- **Outcome:** unit tests agree with `convergenceOutcome`; 400/404 paths covered.

### 4. `/openapi.json`
- OpenAPI 3.1 for the three operations plus `/api/chart.svg`, static in `public/`.
- **Outcome:** valid JSON; a test checks every documented path is routed.

### 5. `/api/chart.svg`
- Embeddable SVG with `<title>`, `<desc>`, canonical `<link>` metadata and the attribution
  line "Mountain to Climb · World Bank · Scenario: …".
- **Outcome:** renders in a browser; XML-escaped; cacheable.

### 6. `/compare/:a/:b` pages
- Server-rendered HTML (facts, scenario, result sentence, static table, inline SVG, caveats,
  link into the app), JSON-LD, canonical, `Accept: text/markdown` and `.md` variants.
- Slugs from country names; ISO3 slugs 301 to the name slug.
- **Outcome:** `/compare/poland/united-kingdom` matches `/api/convergence` for the same inputs.

### 7. Remote MCP server (`/mcp`)
- Streamable HTTP, no auth (public, read-only data), built with the official MCP SDK or
  Cloudflare's agents package rather than a hand-rolled protocol. Check the current spec first:
  the July 2026 revision changed the handshake.
- Tools `compare_countries`, `calculate_convergence`, `growth_required_by_deadline` wrap
  `worker/_lib/scenario.ts`. Descriptions say when to use each and that results are
  scenarios, not forecasts. Responses include `structuredContent` and the `summary` sentence.
- Server `instructions` carry the guidance a skill would (state growth rates, surface caveats).
- Rate limit suited to a public endpoint (the in-memory limiter is per isolate).
- `/.well-known/openai-apps` serves the domain-verification token OpenAI issues for app
  submission (must be on the same domain as `/mcp`).
- **Outcome:** an MCP client can list and call all three tools; results match the REST API.

### 8. Claude skill
- `skills/economic-convergence/SKILL.md`: when to call which tool, always state assumed
  growth rates, call results scenarios, surface `caveats`, link the compare page.
- **Outcome:** the skill loads in Claude Code and drives the connector on a sample question.

### 9. Plugin and distribution
- Claude Code plugin manifest bundling the skill and an `.mcp.json` for the remote server,
  plus a marketplace manifest in this repo.
- Test in ChatGPT first: enable developer mode, add the `/mcp` URL as a connector, and check
  the three tools work. No review is needed for this.
- Later, once the MCP server has real usage (decide who publishes; both need an org account):
  - Claude connector directory (needs a Team/Enterprise org).
  - ChatGPT app directory: verified OpenAI developer account, submission permission,
    reviewer notes (reportedly 3–7 business days). Confirm that a no-auth server is accepted,
    since ChatGPT apps are documented around OAuth. An in-chat chart widget is optional.
- ChatGPT has no skill format, so guidance lives in the MCP `instructions` and tool
  descriptions. Custom GPTs/Actions are being retired; don't build for them. The OpenAPI file
  stays for developers and other agents.
- **Outcome:** one install command gives Claude Code users both skill and connector.

## Open decisions
- `robots.txt` leaves training crawlers (GPTBot etc.) on the default allow rule. Add a
  dedicated `User-agent: GPTBot` block to change that.
- `/api/convergence` now defaults a missing `growth_rate` to the chaser's trailing 10-year
  CAGR (was: CAGR over the whole series) and starts from the latest year both countries have data.
- Routes live in `worker/index.ts`, which is part of the uncommitted Pages → Worker migration.

## What's next
- Review Search Console / server logs after two weeks; grow the curated list from real queries.
- Essay pages if the homepage explainer earns traffic.
- WebMCP (`navigator.modelContext`) registration in the SPA, if browser agents adopt it.
